# Скуратовские котики

Одностраничный сайт-галерея фотографий кофейных стаканчиков. Стиль: чёрный лофт (кирпич, лампа Эдисона) и крафтовая бумага, как на стаканчиках. Крупные фото, на телефоне — вертикальная лента «одно фото на экран».
Посетители могут только смотреть и приближать фото (тап по фото → двойной тап / щипок / колесо мыши). Под каждым фото — его номер, в шапке — счётчик общего количества.

## Как выложить на GitHub Pages

1. Создайте на GitHub **публичный** репозиторий (для бесплатного аккаунта Pages работает только с публичными).
2. Загрузите в него файлы проекта (в корень, ветка `main`): `index.html`, `style.css`, `script.js`, папку `photos`.
   Скрытую папку `.github` загрузить перетаскиванием обычно не получается — создайте файл автозапуска вручную:
   **Add file → Create new file**, в поле имени введите `.github/workflows/pages.yml`
   (после каждого `/` создаётся папка), вставьте содержимое файла `pages.yml` из архива и нажмите **Commit changes**.
3. Откройте **Settings → Pages** и в поле **Source** выберите **GitHub Actions**.
4. Во вкладке **Actions** дождитесь зелёной галочки. Адрес сайта появится в **Settings → Pages**
   (обычно `https://ВАШ-ЛОГИН.github.io/НАЗВАНИЕ-РЕПОЗИТОРИЯ/`).

## Как добавлять фото (администратор)

Администратор — любой, у кого есть право записи в репозиторий.

1. Откройте папку `photos` в репозитории на GitHub.
2. **Add file → Upload files**, перетащите фото, нажмите **Commit changes**.
3. Через ~1 минуту фото появятся на сайте. Всё остальное — автоматически, при публикации:
   - **Порядок и номер.** Фото сортируются по дате коммита, в котором были добавлены: самые новые —
     наверху ленты. Номер под фото — это порядковый номер по дате добавления (1 — самое первое
     загруженное фото), он не зависит от имени файла и не меняется, если фото потом поменять местами.
   - **Счётчик.** Общее количество фото в шапке страницы считается само.
   - **Сжатие.** JPEG и PNG пережимаются в оптимизированный JPEG (качество 82, не крупнее 2000 px
     по длинной стороне, без метаданных) — это может в разы уменьшить вес страницы. GIF не трогаем,
     чтобы не сломать анимацию, WebP/AVIF пережимаются в своём формате.

Удалить фото — открыть файл на GitHub и нажать значок корзины.

В папке лежит пример `photos/01.jpg` — удалите его, когда загрузите свои фото.

Советы:
- Если грузите сразу несколько фото в одном коммите, их взаимный порядок — по имени файла
  (так что `01.jpg` окажется выше `02.jpg` среди фото из одной загрузки).
- Формат HEIC (айфон) браузеры не открывают — конвертируйте в JPG перед загрузкой.
- Сжатие само уменьшает размер фото для показа на сайте, но вес репозитория (место в Git)
  экономит только исходный файл — не обязательно, но лучше заранее не грузить фото тяжелее 8–10 МБ.

## Просмотр на своём компьютере

```bash
python3 -c "import os,json;f=sorted(x for x in os.listdir('photos') if x.lower().endswith(('.jpg','.jpeg','.png','.webp','.gif','.avif')));print(json.dumps([{'file':n,'number':i+1} for i,n in enumerate(f)][::-1],ensure_ascii=False))" > photos.json
python3 -m http.server 8000
```
Откройте http://localhost:8000. Локально фото сортируются по имени файла (а не по дате добавления
и без сжатия) — это только для проверки вёрстки. Файл `photos.json` нужен лишь для этого: на
GitHub он формируется автоматически при публикации, с настоящей сортировкой по дате и сжатием.

## Важно знать

- Сайт статический, поэтому загрузка фото идёт через репозиторий, а не через форму на странице.
- Фото публичны. Сайт не даёт кнопок скачивания и редактирования, но полностью защитить снимки от сохранения
  (скриншот, «сохранить как») в браузере нельзя.
- Если переименовать или перезалить уже существующее фото отдельным коммитом, GitHub
  посчитает это «добавлением» заново, и дата/номер фото обновятся.
